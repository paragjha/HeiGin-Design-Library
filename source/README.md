# Copyable source

The copyable component source is **`packages/ui/src`**, the same files the npm package is built from, so there is no second copy to drift out of date.

`source/manifests/<component>.json` is generated by `npm run manifests` from the real import graph. Each manifest lists:

- `files`: every file to copy (the component, its CSS module, and the internal components and utilities it imports)
- `styles`: `styles/tokens.css`, which is required once per app
- `internalDependencies`: the other HeiGin components it relies on
- `install`: the npm packages to add (`@base-ui/react`, `lucide-react`); React itself is a peer dependency
- `client`: whether the entry module is a Client Component (`"use client"`)

## Copy a component

```bash
node scripts/copy-component.mjs approval-card --dest ../my-app/components/heigin
node scripts/copy-component.mjs --list
node scripts/copy-component.mjs table --dest ./x --dry-run
```

Files keep their layout relative to `src`, so relative imports keep working without rewriting:

```
components/heigin/
  components/ui/button.tsx, button.module.css, spinner.tsx, …
  components/crm/approval-card.tsx, crm.module.css, …
  lib/cn.ts
  styles/tokens.css
```

Then:

1. Run `npm install` with the packages the script prints.
2. Import `components/heigin/styles/tokens.css` once (for example in `app/layout.tsx`).
3. Import components by path, for example `@/components/heigin/components/ui/button`.

`npm run source:check` copies **every** component into an empty directory outside the repo and type-checks it, with only its declared packages resolvable. CI runs it, so a manifest can't hide a dependency.

Manual copying works too: copy exactly the `files` listed in the manifest, keeping their relative paths.
