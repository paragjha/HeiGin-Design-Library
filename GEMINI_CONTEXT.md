## Rules you must follow

1. **Never duplicate counts.** Primitives/patterns/tokens counts are read from `apps/docs/src/generated/catalog.ts`. Don't hardcode "31" or "18" anywhere.
2. **Routes are pushState** (swapped from hash router). `vercel.json` has the SPA rewrite. Every new page needs an entry in `App.tsx`'s route table AND the sidebar `items` array AND the sitemap generator.
3. **`source/licenses.json` is authoritative for paid/free.** build-registry.mjs fails the build if a manifest slug isn't listed. If you add a new manifest or template item, add it to licenses.json too.
4. **No in-tree copies of external component libraries.** We tried Kokonut UI as copy-source; reverted (commit `8a213d8` on 2026-11-12). Pending direct npm imports instead.
5. **Design tokens only.** Dark mode is primary. Use `--hg-*` CSS variables. Light-mode zinc → neutral; emerald/rose/sky/violet/teal/stone → green/red/blue/neutral.
6. **No fake integrations.** If the backend doesn't exist, build the frontend shell + mark the integration point. Don't invent OAuth providers, prices, webhooks.
7. **Attribution for commits:**
   ```
   Co-Authored-By: Gemini Argon <noreply@google.com>
   ```
   (Replace with whatever string your Gemini session uses — but include it, so Claude knows what was Gemini's.)
8. **PR workflow:** `main` is the default branch. The last three Kokonut commits bypassed the PR rule; preferred going forward is a feature branch + PR. Work on branch `restructure/<short-name>`.
9. **Before pushing:** `npm run typecheck -w apps/docs` AND `npm run build -w apps/docs` must pass. If CI's gitleaks or release-verify fails, fix the root cause — don't add an ignore line without understanding why.

## The restructure brief (summary)

Full brief is in the pasted content; condensed:

1. **Split marketing website from documentation.** Marketing pages (`/`, `/components`, `/patterns`, `/blocks`, `/templates`, `/pricing`) use a public nav. Docs pages (`/docs/*`) use the sidebar shell.
2. **Delete Gallery, replace with category tree.** Categories:
   - Foundations: Buttons & Actions, Inputs & Forms, Layout
   - Interface: Navigation, Data Display, Feedback & Status, Overlays & Dialogs, Interactive Elements
   - Every one of the 31 primitives + 18 patterns goes into exactly one leaf. Pick the best fit; no duplicates.
3. **Component pages get a consistent spec:** title, status/metadata, preview, variants, Code/Preview/HTML tabs, install, source copy, API ref, accessibility, related.
4. **New sections — Patterns, Blocks, Templates — each with its own index.** Blocks is new and empty (empty-state is fine).
5. **New landing page at `/`.** Marketing hero + component showcase + patterns/blocks/templates preview + developer workflow + pricing preview + CTA + footer.
6. **Account shells** (no OAuth wiring): Overview, My Library, Saved, Purchases, Billing, MCP Config, Settings.
